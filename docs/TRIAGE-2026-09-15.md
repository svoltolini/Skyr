#### Issue 1: [Security] Owner PIN removal bypass allowed unauthorized profile access

**Labels:** `security`, `priority:P1`

**Description:**
The release audit identified a security finding where profile activation did not properly validate the canonical PIN, allowing unauthorized access to locked profiles. Additionally, profile management operations did not require an authenticated eligible profile, and biometric results could be used without revalidating current state.

**Impact:**
- Unauthorized users could bypass PIN protection on owner profiles
- Profile edits were not tied to their opening session and profile revision
- Remote PIN changes did not properly lock active access or revoke biometric enrollment

**Remediation (completed in batch 1):**
- Profile activation validates the canonical PIN
- Management requires an authenticated eligible profile
- Biometric results revalidate current state
- Edits are tied to their opening session and profile revision
- Remote PIN changes lock active access and revoke biometric enrollment

**Acceptance criteria:**
- [ ] Biometric hardware testing completed
- [ ] Remote profile change scenarios verified
- [ ] Owner/member journeys tested on two Apple Accounts

---

#### Issue 2: [Security] Malformed metadata could cause unbounded memory allocation

**Labels:** `security`, `priority:P1`

**Description:**
The release audit identified a security finding where malformed MP4/ID3 metadata could cause unbounded memory allocation or unsafe arithmetic operations during media parsing.

**Impact:**
- Maliciously crafted audio files could cause memory exhaustion
- Integer overflow in bitrate/duration calculations
- Incomplete declared regions could cause out-of-bounds access

**Remediation (completed in batch 2):**
- MP4/ID3 changes check spans before arithmetic, integer conversion, and slicing
- Reject incomplete declared regions
- Validate optional frame/descriptor prefixes
- Cap complete tag regions
- Avoid unsafe bitrate arithmetic in indexer fallback
- NAS artwork downloads use bounded async byte stream with size checks

**Acceptance criteria:**
- [ ] Fuzzing/boundary tests pass for media parsing
- [ ] No crashes on malformed test files

---

#### Issue 3: [Security] Failed family revocation could leave stale credentials

**Labels:** `security`, `priority:P1`

**Description:**
The release audit identified a security finding where failed family sharing removal could leave stale credentials accessible, and retry attempts could switch context inappropriately.

**Impact:**
- Removed family members might retain access to NAS credentials
- Failed revocation could produce false success result
- Missing legacy credentials handled incorrectly

**Remediation (completed in batch 3):**
- Only credentials verified for the current NAS source are offered
- Sharing removal requires CloudKit acknowledgement before rotating the NAS password
- Failed changes preserve saved pending state and recovery instructions
- Retries cannot switch Apple Account, family, NAS or profile session
- Missing legacy credentials do not produce false success

**Acceptance criteria:**
- [ ] Family removal tested with network interruption
- [ ] Credential rotation verified after successful revocation
- [ ] Retry scenarios tested across account/NAS changes

---

#### Issue 4: [Security] Cross-NAS family credential scoping could expose wrong credentials

**Labels:** `security`, `priority:P1`

**Description:**
The release audit identified a security finding where family credentials were not properly scoped to the specific NAS, potentially exposing credentials from one NAS when connecting to another.

**Impact:**
- Credentials from one NAS could be offered when connecting to a different NAS
- Family access verification was not NAS-specific
- Download lookups could use wrong credential source

**Remediation (completed in batch 3):**
- Catalogue, credentials, family access and download lookup distinguish canonical scheme, hostname, effective port and account
- Only credentials verified for current NAS source are offered
- Old cached audio is not relabelled
- Older hostname-only credentials require fresh sign-in

**Acceptance criteria:**
- [ ] Two real NAS libraries with identical paths tested
- [ ] Credential isolation verified across NAS switches
- [ ] Same-host different-port/account identity tested

---

#### Issue 5: [Security/P2] Oversized cover artwork could cause memory exhaustion

**Labels:** `security`, `priority:P2`

**Description:**
The release audit identified a security finding where oversized cover artwork downloads were not bounded, potentially causing memory exhaustion.

**Impact:**
- Maliciously large artwork files could exhaust device memory
- No limits on advertised size vs actual bytes received

**Remediation (completed in batch 2):**
- NAS whole-file artwork downloads use bounded async byte stream
- Both advertised size and bytes received are checked
- URLSession task cancelled on exit, error, and caller cancellation
- Ranged reads cancel after collecting requested window
- Loops explicitly run off main actor

**Acceptance criteria:**
- [ ] Memory bounds verified with oversized test images
- [ ] Cancellation behavior confirmed
